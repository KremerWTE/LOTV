# Session Startup Directive — LOTV (Restrictive Tier v1.4)

**Purpose:** Optimized startup protocol for Lily of the Valley (LOTV) SaaS Platform
**Version:** v1.4 (restrictive tier)
**Safety Level:** Maximum

## 🚀 Startup Protocol

### Startup Modes (Choose Based on Session Type)

**Quick Mode (NEXT_STEPS only)** - 80% of sessions
- Use when: Resuming recent work, current tasks clear
- Load: `NEXT_STEPS.md` only (~400 tokens)
- Time: <5 seconds
- Best for: Continuation work, straightforward tasks

**Balanced Mode (Context + TODO)** - 15% of sessions
- Use when: Starting new phase, need full task context
- Load: NEXT_STEPS.md + MASTER_TODO.md + latest session (~3-5k tokens)
- Time: ~10 seconds
- Best for: Phase transitions, planning sessions

**Comprehensive Mode (Full Context)** - 5% of sessions
- Use when: Major planning, architecture decisions, complex analysis
- Load: All context files (~8-12k tokens)
- Time: ~15 seconds
- Best for: Major planning, critical decisions

## 🚀 Startup Steps by Mode

### Quick Mode Steps (4 Steps) ⚡ FASTEST

**Step 1: Branch Safety** ⚠️ CRITICAL - MANDATORY

```bash
git branch --show-current
```

**Protected Branches (NO direct commits):**
- **Exact Match:** `main`, `master`, `dev`
- **Contains Pattern:** `beta`, `stage`, `staging`, `production`, `prod`, `deploy`

**Safe Branches for LOTV:** `kremer-dev`, `feature/*`, `fix/*`, `bugfix/*`, `hotfix/*`

**If on `main` → MANDATORY Action:**
```bash
git checkout kremer-dev
# OR create a new feature branch
git checkout -b feature/[FEATURE_NAME]
```

**Step 2: Sync with Remote** (REQUIRED)

```bash
git fetch origin && git pull origin $(git branch --show-current)
```

**Step 3: Load NEXT_STEPS.md ONLY** ⚡

**READ:**
- `NEXT_STEPS.md` (~400 tokens) - Immediate task context

**❌ DO NOT READ in Quick Mode:**
- ❌ MASTER_TODO.md
- ❌ README.md
- ❌ SESSION_STARTUP_DIRECTIVE.md (this file — already read)
- ❌ Session summaries
- ❌ Architecture docs
- ❌ **ANY other files** unless explicitly needed for your specific task

**Step 4: Present Summary**

Show: Branch status, current phase, next 3-5 tasks, recent completion.

---

### Balanced Mode Steps (5 Steps)

**Step 1-2:** Same as Quick Mode (branch safety + sync) - MANDATORY

**Step 3: Load Context Files**

**Required:**
1. **NEXT_STEPS.md** - Immediate tasks
2. **MASTER_TODO.md** (relevant sections only) - Full task context
3. **Latest Session** - `sessions/[LATEST].md`

**Step 4-5:** Analysis and summary

---

### Comprehensive Mode Steps (6 Steps)

**Step 1-2:** Same as Quick Mode (branch safety + sync) - MANDATORY

**Step 3: Load Full Context**

**Load All:**
1. NEXT_STEPS.md
2. MASTER_TODO.md (full)
3. Latest session summary
4. README.md
5. SESSION_STARTUP_DIRECTIVE.md (this file)
6. Relevant docs as needed

**Step 4-6:** Deep analysis, decision documentation, summary

## ⚠️ LOTV-Specific Critical Rules

1. **No sensitive data in commits** — no connection strings, secrets, API keys, or PII
2. **Conventional commits** — use `feat:`, `fix:`, `chore:`, `docs:`, `test:`, `refactor:` prefixes
3. **No AI attribution** — do not add "Generated by Claude" or "Co-Authored-By: Claude"
4. **Ask before deleting** — never delete files, migrations, or database objects without confirmation
5. **Small, focused commits** — commit logically grouped changes
6. **Update NEXT_STEPS.md after every session** — keep task status accurate
7. **Always use `Lotv.slnx`** — `dotnet build Lotv.sln` will fail
8. **Data folder is protected** — only `.md` reference docs go in `data/`
9. **Branch strategy** — feature work on `kremer-dev`; merge to `main` via PR after review
10. **JotForm writes are blocked** — HIPAA-BAA account; all form changes via builder UI only
11. **Production DB** — SQL Server at `10.100.1.87`; no direct AI session access to live data

## 🔄 Session End Protocol — MANDATORY

Before closing a session:
1. Update `NEXT_STEPS.md` — mark completed tasks, add newly discovered tasks (5-7 tasks only)
2. Update `MASTER_TODO.md` if major work (phase completion, significant deliverables)
3. Write a session note to `sessions/YYYY-MM-DD-brief-title.md`
4. Verify checklist (see CRITICAL_RULES_CONSOLIDATED.md §4.1)
5. Push to `kremer-dev`: `git push origin kremer-dev`

## ⚡ Quick Reference

**Every Session Start:**
1. ⚠️ Check branch (MANDATORY) — must be on `kremer-dev` or feature branch
2. 🔄 Sync with remote (REQUIRED)
3. 📖 Load NEXT_STEPS.md (or more if needed)
4. 📝 Present summary

**Every Session End:**
1. 📋 Update NEXT_STEPS.md (ALWAYS)
2. 📋 Update MASTER_TODO.md (if major work)
3. ✍️ Create session summary (MANDATORY)
4. ✅ Verify checklist
5. ⬆️ Push commits to kremer-dev (REQUIRED)

**Protected Branches (NO COMMITS):**
- main, master, dev, *beta*, *stage*, *prod*, *deploy*

**Safe Branches:**
- kremer-dev, feature/*, fix/*, bugfix/*, hotfix/*
